| F-21 | **Blocker** (patch 01) | `framework/dq_framework.py:83` (`df_filtered.cache()`), `:85` (`count()`) | On serverless compute `DataFrame.cache()` raises `[NOT_SUPPORTED_WITH_SERVERLESS] PERSIST TABLE is not supported on serverless compute`. Every table crashes before `open_result_table`, so on serverless (the only compute in Free Edition, and common in company workspaces) the framework evaluates **no rules at all**. Every `run_data_quality` call ends as a `result` row with status `code_error` and no table/rule rows. Reproduced in pilot 1b: 6/6 calls; with the driver shim (cache_mode=auto) the re-run evaluated 24 rules. The dashboard driver works around it with a runtime shim (`bundle/src/driver/cache_shim.py`, `cache_mode=auto`), which the company should **not** need. | Proper fix in `framework/utils.py`: add `def cache_if_supported(df):` → `try: return df.cache()` / `except AnalysisException as e: if 'NOT_SUPPORTED_WITH_SERVERLESS' in str(e): return df` / `raise`, and call it from `dq_framework.py:83` instead of `df_filtered.cache()`. Do the same for any future `persist()`/`unpersist()`. Optionally expose `run_data_quality(..., cache_input='auto'|'on'|'off')` so jobs on classic clusters keep caching, and serverless runs without it. Add a regression test that runs one rule on serverless. Note: without caching, each rule re-reads the filtered partition, so prefer a narrow `filter_field`. |
